[![ci](https://img.shields.io/github/actions/workflow/status/Idfoxes/keelson/ci.yml?branch=main&label=ci)](https://github.com/Idfoxes/keelson/actions/workflows/ci.yml)

**Установите через своего агента.** Откройте Claude Code и отправьте:

```
Install https://github.com/Idfoxes/keelson and set it up.
```

Агент прочитает [AGENTS.md](AGENTS.md), поставит плагин и попросит открыть одну новую сессию, где `/keelson:setup` всё проверит и поставит недельный разбор (понедельник 09:00 по местному времени, одна строка cron, её можно убрать).

Вручную:

```
/plugin marketplace add Idfoxes/keelson
/plugin install keelson@keelson
```

---

Агенты для кода повторяют одни и те же ошибки, а поправка, которую вы дали в понедельник, к среде забыта. Деньги уходят на повторное чтение контекста, и в чате этого не видно.

Keelson это локальная обвязка для Claude Code и Codex. Она записывает на вашей машине каждый ход и каждый вызов инструмента, гоняет ворота качества в конце хода и раз в неделю превращает собранное в правки правил, которые вы принимаете или отбрасываете. Это хуки, скрипты, скиллы и обычные файлы: без сервера, без аккаунта, без телеметрии.

Статус: бета, версия 0.1.0 ([что пока сырое](#статус-и-ограничения)). English version: [README.md](README.md).

```

  <amount>  a41f09c2  webapp        calls <n>, average context <k>
  <amount>  7c20be11  billing-api   calls <n>, average context <k>

$ node <plugin-dir>/scripts/findings.mjs stats --days 7

  contract         <n>  <share> %

$ node <plugin-dir>/scripts/dashboard.mjs --no-open

```

Скрипты печатают текст по-английски. Выше показан пример вывода: значения заменены заглушками.

Дашборд это одна самодостаточная HTML-страница: запросы по дням, самые длинные сессии, вопросы, которые вы задаёте снова и снова, уроки, находки по классам, самые дорогие сессии и то, что принесло больше всего токенов в последнюю сессию.

- **Записи.** Каждый запрос (с маскировкой), ход и вызов инструмента пишется в обычные файлы в `~/.agent`. Видно, куда ушли токены и что вы поправляете снова и снова.
- **Ворота.** В конце хода один диспетчер запускает ворота качества, сверку утверждений с журналом действий, проверку доказательств, проверку ревью, проверку «проснусь сам» и проверку «сначала push». Опасные команды и правки защищённых файлов останавливаются до выполнения.
- **Недельный разбор.** Команда `/keelson:weekly-review` читает данные недели и пишет отчёт с предложенными уроками и правилами, у каждого есть доказательство и готовая команда. Сама она ничего не меняет.

## Наблюдения одного пользователя

Дизайн вырос из личных журналов одного человека за недели ежедневной работы. Это наблюдения, а не контролируемые эксперименты, у вас данные будут другие.

- **Завершённые сессии продолжали тратить.** Большая доля ходов модели за измеренную неделю пришлась на сессии, которые уже передали работу новой сессии. Старые сессии будили их собственные напоминания, фоновые уведомления и сообщения дочерних сессий, и они отвечали, что продолжение уже идёт.
- **Сжатие на месте остановило цепочки.** После включения сжатия при фиксированном размере контекста (настройка Claude Code `autoCompactWindow`, Keelson её за вас не меняет) призывы продолжать после передачи прекратились.
- **Рабочие субагенты стартовали тяжёлыми.** Рабочий субагент без заявленного списка инструментов стартовал с заметно большим контекстом, чем с заявленным списком, а стартовый контекст пересылается с каждым его запросом.
- **Общий файл записей породил правочные коммиты.** Записи проекта, которые ветки задач не должны править (контекст, решения, журнал сессий), правили на ветках задач, и многие коммиты, которые их трогали, только их восстанавливали. Проверка шла после коммита. Теперь хук отказывает в правке до того, как она случилась.

## Быстрый старт

Требования: Claude Code с поддержкой плагинов, Node 18 или новее, git. Разработано и проверено на macOS и Linux. Windows не проверялся.

Установите как выше и начните новую сессию. Работайте как обычно. Через несколько запросов посмотрите первые данные. `<plugin-dir>` это папка, в которую Claude Code установил плагин (внутри `~/.claude/plugins/`), или `plugins/keelson` внутри клона этого репозитория.

```
node <plugin-dir>/scripts/dashboard.mjs --no-open
```

Команда пишет `~/.agent/dashboard.html`, страницу за последние 7 дней (`--days N` меняет период). Без `--no-open` страница открывается командой macOS `open`. Некоторые разделы пустые: они читают данные, которые этот пакет не пишет.

Команды, которыми вы будете пользоваться:

```
node <plugin-dir>/scripts/context-ledger.mjs --cost --days 7
node <plugin-dir>/scripts/context-ledger.mjs --report --last
node <plugin-dir>/scripts/findings.mjs stats --days 7
node <plugin-dir>/scripts/findings.mjs acted --days 14
node <plugin-dir>/scripts/learn.mjs suggest --days 14
node <plugin-dir>/scripts/lessons.mjs list
node <plugin-dir>/scripts/recall.mjs "what I am looking for"
node <plugin-dir>/scripts/handoff.mjs show
```

По порядку: стоимость повторной отправки контекста по моделям и сессиям; что принесло токены в последнюю сессию; находки ревью и ворот по классам; сколько находок закончилось правкой; классы находок, которые повторились три раза за 14 дней в одном репозитории и годятся в кандидаты на правило; сохранённые уроки; поиск по вашему журналу, передачам, находкам, урокам и записям решений; последняя записка передачи для текущего репозитория.

Чтобы записать поправку, которая вернётся в нужный момент, выполните:

```
node <plugin-dir>/scripts/lessons.mjs add "Run the migration test before the whole suite" --when "fix the migration; migration" --evidence "what you said"
```

Добавьте `--global` для урока, который верен во всех репозиториях. Когда в следующем запросе есть слова из `--when` (сравнение идёт по основам слов, поэтому берите характерные слова), хук добавляет урок в этот ход.

Чтобы дать репозиторию память проекта в git (`AGENTS.md`, `.agent/context.md`, журнал сессий, решения, инциденты, карта кода):

```
node <plugin-dir>/scripts/agent-context.mjs init
```

`agent-context.mjs check` проверяет бюджеты и отмечает строки, похожие на секреты.

## Недельный разбор

Хуки собирают данные всю неделю. Разбор превращает их в решения. Запускайте его раз в неделю в Claude Code:

```
/keelson:weekly-review
```

Команда запускает `findings.mjs stats --days 7`, `findings.mjs acted`, `learn.mjs suggest --days 14` и `context-ledger.mjs --cost --days 7`, читает прошлый отчёт из `~/.agent/reviews/`, если он есть, проверяет, что стало с его предложениями, и пишет `~/.agent/reviews/<date>.md`:

- что стало с предложениями прошлой недели;
- главные источники расходов;
- классы находок, которые повторялись;
- до пяти предложенных правок, у каждой строка с доказательством и готовая команда (`lessons.mjs add ...` или JSON правила в теневом режиме);
- список того, что она просмотрела и советует не трогать.

Команде разрешены только `node`, Read и Write. Она никогда не правит правила, настройки и файлы репозитория. Вы читаете отчёт и запускаете команды, с которыми согласны. [docs/sample-weekly-report.md](docs/sample-weekly-report.md) показывает формат на выдуманных данных. Команду можно также запускать из вашей собственной задачи по расписанию.

## Что куда пишется

Всё это обычные файлы на вашей машине.

| Путь | Содержимое |
|---|---|
| `~/.agent/journal/YYYY-MM.jsonl` | Каждый запрос с маскировкой, не больше 400 символов |
| `~/.agent/turns.jsonl` | Строка на завершённый ход: время, сессия, репозиторий, размер контекста, последние 200 символов ответа (с маскировкой) |
| `~/.agent/context-ledger/<session>.jsonl` | Строка на вызов инструмента: инструмент, цель (путь файла или первые 60 символов команды), возвращённые токены, размер контекста, модель |
| `~/.agent/findings.jsonl` | Находки ревью и ворот: класс, важность, `file:line`, доказательство |
| `~/.agent/lessons.jsonl` | Записанные вами поправки с фразами-триггерами и счётчиком подтверждений |
| `~/.agent/handoff/` | Записки передачи между сессиями, по одной на репозиторий |
| `~/.agent/hook-runs.jsonl` | Строка на запуск стража с его исходом |
| `~/.agent/denials.jsonl` | Отказы в разрешениях с причиной от классификатора |
| `~/.agent/board/` | Одна карточка на сессию |
| `~/.agent/reviews/` | Отчёты недельного разбора |
| `~/.agent/dashboard.html` | Сгенерированная страница |
| `~/.agent/*.json`, `trusted-repos.txt` | Небольшие файлы состояния стражей |
| `<repo>/AGENTS.md`, `<repo>/.agent/` | Память проекта в git: контекст, журнал сессий, решения, инциденты, карта кода. Создаётся `agent-context.mjs init`, предназначена для коммита |

В версии 0.1.0 ничто не ротирует журналы.

## Что делает каждый хук

Шестнадцать записей хуков, все из `plugins/keelson/hooks/hooks.json`. Каждая это один процесс `node`. Страж, которому нечего сказать, ничего не печатает и не тратит контекст.

| Событие | Скрипт | Что делает |
|---|---|---|
| UserPromptSubmit | `journal.mjs` | Добавляет запрос с маскировкой в журнал. Ничего не печатает |
| UserPromptSubmit | `context-guard.mjs` | Предупреждает на 120k токенов контекста, на 260k просит передачу и новую сессию. Молчит ниже 120k |
| UserPromptSubmit | `lessons.mjs` | Добавляет сохранённый урок в ход, когда запрос совпадает с его фразами-триггерами. Иначе молчит |
| SessionStart | `build-policy.mjs --hook` | Подставляет файлы правил при запуске, clear и compact |
| SessionStart | `handoff.mjs` | При запуске и clear подставляет передачу для той же ветки, контекст проекта из `.agent/context.md` (в пределах 6000 символов) и последнюю запись журнала. После сжатия подставляет контекст проекта заново |
| SessionEnd | `agent-context.mjs session-end` | Если сессия меняла файлы или делала коммит, а агент не написал запись журнала, добавляет автоматическую |
| PostToolUse | `context-ledger.mjs` | Пишет одну строку журнала на вызов инструмента. Предупреждает, когда один и тот же вызов повторился пять раз подряд |
| PermissionDenied | `permission-denied.mjs` | Пишет отказ и причину классификатора, разрешает до трёх повторов за десять минут |
| PreToolUse | `protect-guard.mjs` | Отказывает в правках `.agent/context.md`, `.agent/log.md` и `.agent/decisions.md` на ветках задач и путей из `.agent/protected` |
| PreToolUse | `cron-guard.mjs` | Отказывает в повторяющихся напоминаниях чаще чем раз в 30 минут |
| PreToolUse | `destructive-guard.mjs` | Спрашивает перед командами, которые удаляют или перезаписывают данные (рекурсивный `rm`, удаления в хранилищах, `kubectl delete` вне тестового пространства имён, `docker prune`, force push, hard reset), и запрещает читать секреты из связки ключей |
| PreToolUse | `model-route.mjs` | Отправляет задачи поиска и чтения субагента general-purpose на Haiku и требует явную модель для остальных |
| PreToolUse | `reuse-guard.mjs` | Останавливает первый новый файл кода или функцию, пока в последние 30 минут не было поиска `reuse-scout` |
| Stop | `turn-log.mjs` | Пишет строку хода и обновляет карточку сессии. Никогда не блокирует |
| Stop | `stop-dispatch.mjs` | Запускает шесть проверок параллельно и возвращает один общий блок, перечень ниже |

Диспетчер запускает `quality-gate.mjs` (линтер, синтаксис и затронутые тесты для файлов, изменённых за ход, лишние файлы, новые комментарии, если проект их запрещает), `claims-guard.mjs` (утверждения в итоговом ответе против журнала действий: «тесты прошли» требует запуска тестов в этом ходе), `stop-evidence-guard.mjs` (ссылка после push, «готово» без проверки после правки), `review-guard.mjs` (ревью свежим субагентом перед «готово» после более чем 50 изменённых строк), `wake-guard.mjs` («продолжу сам», когда нечему разбудить сессию) и `push-first-guard.mjs` (ответы, которые ждут полного прогона тестов, когда можно сначала сделать push). Блок стоит одного лишнего хода модели, поэтому они приходят одним блоком. Как всё устроено, описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

В пакет также входят 12 файлов правил (подставляются при старте сессии), шесть скиллов (`bootstrapping-project-context`, `critic`, `goal-loop`, `production-debugging`, `project-memory`, `session-diary`) и три субагента (`diff-reviewer`, `log-reader`, `reuse-scout`).

## Накладные расходы

- **Хуки.** 16 записей. По событиям: UserPromptSubmit 3, SessionStart 3 (две срабатывают при запуске и clear, две при compact), SessionEnd 1, PostToolUse 1 (каждый вызов инструмента), PermissionDenied 1, PreToolUse 5 (фильтруются по matcher, вызов Bash запускает два), Stop 2.
- **Время на спокойной машине.** Замер на виртуальной машине Linux с Node 22 и небольшим репозиторием, медиана из 20 запусков: от 14 до 23 мс на хук против 11 мс у пустого `node -e 0`. Диспетчер Stop со всеми шестью проверками: 60 мс.
- **Время в ежедневной работе.** Диспетчер Stop и ворота качества пишут своё время в `hook-runs.jsonl`, так что свои числа можно прочитать. Хвост даёт запуск затронутых тестов в воротах. Бюджет ворот 60 с (`KEELSON_GATE_BUDGET_MS`), диспетчер обрывается через 100 с. Остальные хуки время не пишут.
- **Подставляемый контекст.** 12 файлов правил занимают около 7,5 КБ (7435 байт), подставляются один раз при запуске, clear и compact; по грубой оценке 4 символа на токен это около 1900 токенов. Токенайзером не измерялось. Передача и контекст проекта добавляют не больше 6000 символов контекста проекта плюс записка передачи (до 40 строк): 1961 символ в небольшом тестовом репозитории, ничего, если нет `.agent/context.md` и нет передачи. На каждый запрос ничего не добавляется, пока не сработал урок или контекст не перешёл 120k токенов.

## Приватность

Всё остаётся на вашей машине. Хуки и скрипты не открывают сетевых соединений. Ваш агент общается со своим провайдером, как и раньше; Keelson не добавляет в этот трафик ничего, кроме текста правил, уроков и передач, которые подставляет в сессию.

`lib/redact.mjs` маскирует секреты перед записью текста, по шаблонам: блоки закрытых ключей, известные форматы токенов, пароли в URL, `NAME=value` для имён с PASSWORD, SECRET, TOKEN или API_KEY, значения после меток вроде `AK:` или `password:`, адреса электронной почты, адреса IPv4, внутренние на вид имена хостов, секретные параметры URL и шестнадцатеричные строки от 32 символов. Он работает на запросах (журнал), хвосте каждого ответа, доказательствах находок, причинах отказов и тексте команд в журнале запусков хуков и в журнале вызовов. Журнал вызовов оставляет длинные шестнадцатеричные строки, чтобы хеши коммитов читались.

Чего он не покрывает: пути файлов, всё, что агент или вы пишете в записки передачи, уроки и файлы `.agent/`, и любой секрет, не подходящий ни под один шаблон. Маскировка работает по возможности и не гарантирует защиту. `agent-context.mjs check` отмечает в `.agent/` строки, похожие на секреты. Файлы создаются с вашей обычной umask; `chmod -R go-rwx ~/.agent` оставляет доступ только вам. Не коммитьте `~/.agent`. Подробнее в [SECURITY.md](SECURITY.md).

## Codex

Что работает сегодня, подключается через `install-codex.sh`:

- **Хуки.** Двенадцать записей хуков из восьми скриптов в `~/.codex/hooks.json`: `journal.mjs`, `destructive-guard.mjs` (дважды), `quality-gate.mjs`, `claims-guard.mjs`, `stop-evidence-guard.mjs`, `turn-log.mjs`, `wake-guard.mjs` и проба `codex-probe.mjs` (четыре записи), которая фиксирует, какие события срабатывают. Ваши остальные хуки и их порядок не затрагиваются. Codex просит доверять новым хукам: подтвердите их, иначе они не запустятся. Проба показала, что срабатывают SessionStart, PreToolUse, PostToolUse и Stop.
- **Скиллы.** Шесть скиллов копируются в `~/.agents/skills`.
- **AGENTS.md.** `node <plugin-dir>/scripts/agent-context.mjs init` пишет в `AGENTS.md` проекта блок, которому следует любой агент, читающий `AGENTS.md`, включая Codex: сначала читать `.agent/context.md`, в конце писать журнал сессии и решения.

Не работает в Codex: файлы правил (они приходят через хук SessionStart Claude Code; их можно напечатать командой `node <plugin-dir>/scripts/build-policy.mjs` и самим добавить в `~/.codex/AGENTS.md`), стражи субагентов и диспетчер Stop. Сторона Codex использовалась заметно меньше, чем сторона Claude Code.

```
git clone https://github.com/Idfoxes/keelson
cd keelson
./install-codex.sh
```

Скрипт копирует скрипты в `~/.keelson/plugin`, чтобы хуки работали, если вы переместите клон. Обновление: `git pull && ./install-codex.sh`. Полное удаление: `./install-codex.sh --uninstall` (ваши данные в `~/.agent` остаются). `KEELSON_HOME`, `CODEX_HOME` и `KEELSON_SKILLS_DIR` меняют расположение.

## Переносимость

Вся память это обычные файлы на вашей машине: журнал, уроки, находки, передачи, журнал ходов и журнал вызовов инструментов в `~/.agent`, а также записи проекта в `.agent/` внутри каждого репозитория. Ничего из этого не хранится в аккаунте провайдера. Если вы потеряли доступ к одному провайдеру, запустите другого агента в том же репозитории. Он читает те же `AGENTS.md` и `.agent/context.md`, те же хуки продолжают писать в тот же `~/.agent`, `recall.mjs` ищет по истории, а `handoff.mjs show` печатает последнюю записку передачи.

## Вопросы и ответы

**Отправляет ли это данные куда-нибудь?** Нет. Хуки и скрипты не открывают сетевых соединений, телеметрии нет. Всё пишется в `~/.agent` и, если вы запустили `agent-context.mjs init`, в `.agent/` ваших репозиториев. Стражи, которые блокируют ход, добавляют текст в разговор, поэтому этот текст уходит вашему провайдеру модели, как и всё остальное в сессии.

**Замедляет ли это Claude Code?** Почти нет. Хук это один процесс `node` на 14-23 мс на спокойной машине. Диспетчер Stop там занимает около 60 мс, в ежедневной работе хвост длиннее, когда ворота качества запускают ваши тесты (см. [Накладные расходы](#накладные-расходы)). Блок диспетчера Stop стоит одного лишнего хода модели.

**Можно ли использовать только часть хуков?** Плагин ставит все 16 одним набором. Чтобы запускать меньше, либо ограничьте проверки Stop переменной окружения `KEELSON_STOP_CHECKS` (список имён скриптов через запятую, например `quality-gate.mjs,claims-guard.mjs`) в блоке `env` настроек Claude Code, либо не ставьте плагин и зарегистрируйте отдельные скрипты в своём `settings.json` командой вроде `node /path/to/keelson/plugins/keelson/scripts/destructive-guard.mjs`. У порогов тоже есть переменные: `AGENT_CTX_WARN_TOKENS`, `AGENT_CTX_STOP_TOKENS`, `KEELSON_REVIEW_MIN_LINES`, `KEELSON_GATE_BUDGET_MS`. Подробнее в [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

**Как удалить?** См. [Удаление](#удаление). Ваши данные в `~/.agent` остаются, пока вы их не удалите.

**Чем это отличается от CLAUDE.md?** CLAUDE.md это просьба, которую модель может выполнить или нет, и он не видит, что произошло. Keelson добавляет то, чего не может текстовый файл: хуки, которые проверяют результат в конце хода и отклоняют ход с утверждением «тесты прошли» без их запуска, журнал того, что сделала и сколько стоила каждая сессия, и недельный цикл, который превращает повторяющиеся поправки в уроки и правила с доказательствами. Он также пишет и читает контекст в духе CLAUDE.md (`AGENTS.md` и `.agent/context.md`), так что они работают вместе.

## Удаление

Claude Code:

```
/plugin uninstall keelson@keelson
/plugin marketplace remove keelson
```

Codex: `./install-codex.sh --uninstall`. Чтобы удалить и собранные данные, удалите `~/.agent`. Папки `.agent/` внутри ваших репозиториев ваши; удалите их, если они не нужны.

## Статус и ограничения

Бета, 0.1.0. Что пока сырое:

- Сообщения хуков, файлы правил и дашборд на английском. Несколько эвристик (детектор утверждений «готово», детектор «продолжу сам», маршрутизатор Haiku) распознают английские и русские фразы, английское покрытие тоньше.
- Опубликованных замеров пока нет. Приведённые тайминги получены на одной виртуальной машине Linux, у вас числа будут другие.
- Поведенческие тесты лежат вне этого пакета. CI здесь проверяет синтаксис, манифесты, заголовки скиллов, что каждый хук указывает на поставляемый скрипт и что каждый страж чисто завершается на тестовой нагрузке.
- Передача, которая сама открывает следующую сессию, работает только в настольном приложении Claude Code. В остальных местах агент пишет передачу и просит вас начать новую сессию.
- Журналы не ротируются.
- Разработано и проверено на macOS и Linux. Windows не проверялся. Дашборд открывается командой macOS `open`.
